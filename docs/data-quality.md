# Historical GMX execution data: quality assessment

The frozen extract supports descriptive **opening-based address retention** within its stated scope. Local uniqueness, timestamp, partition and population checks passed. A complete indexed extraction is not proof that the indexer contains every on-chain execution, and the historical decrease classification cannot establish voluntary trading.

The dataset contains **907,107 successful indexed executions** from **123,985 protocol accounts** on Arbitrum One, over `[2023-09-20 00:00:00, 2024-05-29 00:00:00)` UTC. One row represents one execution identified by `(chain_id, transaction_hash, block-global execution log_index)`. Only GMX perpetual order types 2–7 are queried. Swaps, LP actions, cancelled orders and failed executions are outside this dataset. Addresses are not unique people.

The [public audit receipt](../data/evidence/history-quality/audit.json) and [252-day quality table](../data/evidence/history-quality/daily.csv) were generated by an [independent Python standard-library audit](../scripts/audit_history.py). It does not import DuckDB, the analyzer, or the metric SQL. The exact CSV SHA-256 is `76e4992debf0bf2e60328221c94c840aa97c2c7545550085bcd3e83d09fe61a3`. Extraction completed on **2026-10-03 UTC**; this is an intentionally frozen historical snapshot, not a live activity feed.

## Grain, coverage and missingness

| Check | Observed result | Consequence |
| --- | ---: | --- |
| Contiguous seven-day partitions | 36; exact coverage boundaries, no gap or overlap | The requested extraction windows were assembled correctly |
| UTC days containing execution rows | 252 of 252 | No completely empty day in the requested scope |
| Duplicate normalized execution keys | 0 of 907,107 | Repeated local execution IDs do not inflate address counts |
| Execution outside declared coverage | 0 | Campaign and follow-up predicates apply to bounded data |
| Order creation later than execution | 0 | No observed impossible timestamp ordering |
| Missing net position fee | 0 of 907,107 | No missing fee is silently converted to zero |
| Missing order creation | 6,932 of 907,107 (0.76%) | All missing values occur on zero-size collateral actions |
| Missing creation on positive increases | 0 of 480,267 | Strict opening-return metric is available in this snapshot |
| Missing fee on positive increases | 0 of 480,267 | Opening-fee comparisons have complete field coverage |

The action counts are **480,267 increases**, **336,912 decreases**, **54,939 type-7 liquidation records**, and **34,989 zero-size collateral actions**. Every zero-size execution is classified as collateral and excluded from positive-size participation. All rows have `success=true` because the source query selects `OrderExecuted`; this is a selection rule, not an estimated protocol execution success rate. Full fee population does not independently establish fee correctness; the separate [receipt validation](event-validation.md) checks only five deliberately selected March transactions and one collateral asset.

## September activity surge

The partition `[2023-09-27, 2023-10-04)` contains **152,031 events** from **75,525 addresses**. Counts rise from 5,440 events on September 26 to a peak of 34,837 on October 1. The raw order-type counts reconcile with the normalized partition:

| Order type | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Executions | 82,090 | 1,258 | 64,534 | 590 | 595 | 2,964 |

This is a broad address surge, not concentration in one observed account: the busiest address has 178 events; the top 756 addresses (ceiling of 1%) account for 10,127 events, or **6.66%**. There are 13,964 single-event and 57,247 two-event addresses in this partition. Among its 83,119 positive increases, the floor-based 10th, 50th and 90th size percentiles are approximately **$2.30, $6.66 and $158.46**. Only **1,584** of these 75,525 addresses also qualify for the later STIP campaign cohort.

A plausible contextual explanation is the earlier **Odyssey: Reignited** task campaign. Arbitrum's September 19 announcement states that it started September 26, 2023, with GMX featured in the first week. The organizer's Galxe quest lists a leveraged GMX V2 trade as a task. This timing is consistent with the observed surge; it does not identify individual task participants or prove causation. [Arbitrum announcement](https://blog.arbitrum.io/arbitrum-odyssey-reignited/), [organizer's GMX quest](https://app.galxe.com/quest/arbitrum/GCsqgUtsTX).

The prior observed-address group may therefore contain earlier task exposure and cannot serve as an untreated control. High address counts and small orders do not establish bots or Sybils. Independent receipts from the September burst have not been replayed here; the five March receipt checks do not validate this earlier deployment period.

## Independent population and retention recount

The audit scans CSV rows into address sets using exact decimal positivity and explicit UTC intervals. The fixed cohort is the **22,145 accounts** with a successful positive-size increase during `[2023-11-15 00:00:01, 2024-03-27 00:00:00)` UTC. Nonreturning accounts remain in every denominator. The independent recount agrees with the [published analyzer results](../reports/gmx-stip/results.json):

| Metric | Window, UTC | Returning accounts / fixed cohort |
| --- | --- | ---: |
| R30 opening return | April 19–26, exclusive end | 954 / 22,145 |
| Cumulative 30-day opening return | March 27–April 26, exclusive end | 2,997 / 22,145 |
| Sustained R30, at least two active UTC dates | April 19–26, exclusive end | 473 / 22,145 |
| Strict R30, order created at/after March 27 | April 19–26, exclusive end | 954 / 22,145 |
| R60 opening return | May 19–26, exclusive end | 1,126 / 22,145 |
| Open-or-decrease R30 | April 19–26, exclusive end | 1,101 / 22,145 |
| Voluntary R30 including closes | Same R30 window | Withheld: ADL classification unresolved |

The first-observed history breakdown also reconciles: **18,129 first observed during the campaign, 608 R30 returns**; **4,016 observed earlier, 346 R30 returns**. Earliest observed activity uses positive increases or indexed decreases; some decreases may be ADL. These are bounded observation-history labels, not verified acquisition or human-user categories. GMX V2 was operating before the September 20 extraction start.

## Material risks and allowed claims

- **High, confirmed semantic gap:** historical GMX ADL creates a market-decrease order and marks a secondary ADL order type. The public indexer fields used here omit that secondary type. The 1,101 open-or-decrease returns cannot be asserted to be voluntary. Voluntary30 is withheld; opening-based R30 is unaffected. [Historical AdlUtils](https://github.com/gmx-io/gmx-synthetics/blob/ff4b95bc0961586bdf704bcb493b12f6d225ec12/contracts/adl/AdlUtils.sol), [historical AdlHandler](https://github.com/gmx-io/gmx-synthetics/blob/ff4b95bc0961586bdf704bcb493b12f6d225ec12/contracts/exchange/AdlHandler.sol).
- **High, unresolved source completeness:** keyset pagination, empty terminal pages, contiguous partitions and local checks establish successful extraction from the queried indexer. They cannot detect an execution missing from that indexer. A full independent log replay or comparable indexer reconciliation is needed before asserting population completeness.
- **Medium, confirmed left truncation:** pre-September activity is unavailable. Earlier task exposure is documented. Observed-history differences support segmentation, not a treatment-control estimate.
- **Medium, confirmed source-selection limit:** excluding zero-size, liquidation and nontrading actions is intentional. Retention means renewed positive-size position opening, not every interaction with GMX.
- **High, confirmed attribution limit:** campaign execution accounts are not necessarily verified paid rebate recipients. Published receiver overrides also prevent a reliable trader-level reward-cost join. See [reward evidence](reward-data.md); unit acquisition cost and causal ROI remain unavailable.

Keep checksum, duplicate-key, partition-boundary, timestamp-order and denominator reconciliation checks when refreshing. Changes in volatile event counts should trigger investigation, not automatic rejection. Do not remove the September observations solely because their volume is unusual.


This recreates the public daily aggregate and audit receipt, and checks available analyzer summary counts.
